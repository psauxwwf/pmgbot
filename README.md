# pmgbot

`pmgbot` automates blacklist maintenance in Proxmox Mail Gateway (PMG) using messages that were deleted as spam.

The project is intended for environments where an operator or PMG deletes spam messages and the senders of those messages should be automatically added to a PMG `Who` object, for example `Blacklist-pmgbot-autogenerated`.

## How It Works

`pmgbot` performs three main operations:

1. Finds deleted spam messages in `journalctl` for the `pmgproxy` and `pmgdaemon` units.
2. Extracts sender email addresses from the discovered spool files.
3. Imports missing email addresses into a PMG `Who` object through `pmgsh`.

The sender is extracted from message headers:

1. `Return-Path` is preferred.
2. If `Return-Path` is not found, `From` is used.

Email addresses are normalized before processing: surrounding whitespace is trimmed and the value is lowercased.

## Commands

### parse

Collects senders from deleted spam messages and writes them to a blacklist file.

```bash
pmgbot parse --blacklist blacklist.txt --before 30m
```

What `parse` does:

- reads `journalctl -u pmgproxy -u pmgdaemon --since ...`;
- finds paths like `/var/spool/pmg/cluster/.../spam/...`;
- reads the discovered files;
- extracts sender email addresses;
- merges them with the existing `blacklist.txt` content;
- writes the unique list back to `blacklist.txt`.

If `blacklist.txt` does not exist, it is created when the result is written.

### import

Imports email addresses from the blacklist file into a PMG `Who` object.

```bash
pmgbot import \
  --blacklist blacklist.txt \
  --exclude exclude.txt \
  --name Blacklist-pmgbot-autogenerated
```

What `import` does:

- reads `blacklist.txt`;
- reads `exclude.txt` if it exists;
- applies regexp exclusions from `exclude.txt`;
- finds the PMG `Who` object by name through `pmgsh get /config/ruledb/who`;
- reads existing email addresses in that object;
- creates only missing email addresses through `pmgsh create /config/ruledb/who/<id>/email --email <email>`.

If `exclude.txt` does not exist, this is not an error. It behaves the same as an empty exclude file.

### daemon

Periodically collects deleted spam senders and imports them into PMG immediately, without writing an intermediate `blacklist.txt` file.

```bash
pmgbot daemon --config pmgbot.yaml
```

The daemon runs this cycle:

1. collects senders for the last `daemon.before` interval;
2. applies `exclude` patterns;
3. imports missing email addresses into the PMG `Who` object;
4. waits for `daemon.every` and repeats the cycle.

## Configuration

Create a default configuration file:

```bash
pmgbot --save-config --config pmgbot.yaml
```

Example `pmgbot.yaml`:

```yaml
log_level: info
log_path: ""
sudo: true
blacklist: blacklist.txt
exclude: exclude.txt
daemon:
  before: 30m0s
  every: 15m0s
  parse_timeout: 10m0s
  importer_who_name: Blacklist-pmgbot-autogenerated
  import_timeout: 10m0s
```

Fields:

- `log_level`: log level, supports `debug`, `info`, `warn`, and `error`.
- `log_path`: path to a JSON log file; if empty, logs are written only to stderr.
- `sudo`: run external commands through `sudo`.
- `blacklist`: path to the sender file used by `parse` and `import`.
- `exclude`: path to the regexp exclusion file.
- `daemon.before`: how far back to search for deleted spam messages.
- `daemon.every`: how often to run the daemon cycle.
- `daemon.parse_timeout`: timeout for sender collection.
- `daemon.importer_who_name`: PMG `Who` object name used for imports.
- `daemon.import_timeout`: timeout for PMG imports.

Durations use Go duration syntax, for example `30m`, `1h`, or `10m0s`. A bare number is treated as minutes.

## exclude.txt

Each non-empty line in `exclude.txt` is a Go regexp.

Example:

```regexp
^[^@]+@domain\.com$
^service@bob\.com$
@example\.org$
```

Important rules:

- `*` is not a wildcard by itself like it is in shell globs.
- The regexp equivalent of `*` is `.*`.
- A dot in a domain must be escaped as `\.`.
- Use `^` and `$` anchors for exact matches.
- All patterns and email addresses are lowercased before matching.
- Empty lines are ignored.
- Comments are not supported: a line like `# comment` is treated as a regexp.
- If a regexp is invalid, the import fails with a pattern compilation error.

## Regexp Examples

### Domains

| What to exclude                                                         | Line in `exclude.txt`            |
| ----------------------------------------------------------------------- | -------------------------------- |
| Any direct email at `domain.com`, equivalent to `*@domain.com`          | `^[^@]+@domain\.com$`            |
| Any email ending with `@domain.com`                                     | `@domain\.com$`                  |
| Any email at `domain.com` or `example.com`                              | `^[^@]+@(domain                  | example)\.com$` |
| Any email on subdomains of `domain.com`, for example `a@sub.domain.com` | `^[^@]+@[^@]+\.domain\.com$`     |
| Any email at `domain.com` and any of its subdomains                     | `^[^@]+@([^.@]+\.)*domain\.com$` |
| Any email on `.ru` domains                                              | `^[^@]+@[^@]+\.ru$`              |
| Any email on `.com` or `.net` domains                                   | `^[^@]+@[^@]+\.(com              | net)$`          |

### Specific Emails

| What to exclude                                   | Line in `exclude.txt`      |
| ------------------------------------------------- | -------------------------- |
| Only `email@bob.com`                              | `^email@bob\.com$`         |
| Only `admin@domain.com`                           | `^admin@domain\.com$`      |
| `admin@domain.com` and `support@domain.com`       | `^(admin                   | support)@domain\.com$` |
| Any `no-reply` sender on any domain               | `^no-reply@[^@]+$`         |
| Any sender whose local part starts with `bounce-` | `^bounce-[^@]*@[^@]+$`     |
| Any sender whose local part contains `mailer`     | `^[^@]*mailer[^@]*@[^@]+$` |

### Partial Matches

You can write a regexp without `^` and `$`; in that case, the match is searched anywhere inside the email address.

```regexp
@domain\.com$
```

This pattern excludes email addresses ending with `@domain.com`.

```regexp
bob\.com
```

This pattern excludes any email address that contains `bob.com`.

For exact email matches, prefer a full pattern with `^` and `$`:

```regexp
^email@bob\.com$
```

## Build And Test

Build:

```bash
task build
```

Run tests directly:

```bash
go test ./...
```

`task test` in this project runs `go fix ./...` before `go test ./...`.

## Systemd

The repository includes an example `pmgbot.service` unit file.

Expected installation layout:

```text
/opt/pmgbot/pmgbot
/opt/pmgbot/pmgbot.yaml
```

The unit runs:

```bash
/opt/pmgbot/pmgbot daemon --config /opt/pmgbot/pmgbot.yaml
```
